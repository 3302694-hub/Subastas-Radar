# SubastaRadar — агрегатор государственных аукционов Испании

Каталог государственных аукционов с Портала аукционов BOE (судебные, нотариальные,
налоговые и прочие административные): поиск, фильтры, карта по провинциям, избранное,
сохранённые поиски, регистрация с бесплатным периодом, RSS и автопостинг в Telegram.
Интерфейс на испанском, английском и русском.
**Новые аукционы появляются на сайте автоматически** — по расписанию без вашего участия.

```
subastas-espana/
├── scraper/
│   ├── boe.py          # парсер страниц subastas.boe.es (поиск, карточка, имущество)
│   └── scrape.py       # сборщик: новые аукционы → JSON + RSS + Telegram
├── site/               # статический сайт (можно хостить где угодно)
│   ├── index.html
│   ├── config.js       # название, язык по умолчанию, ссылка на Telegram
│   ├── assets/         # app.js, auth.js, style.css, i18n.js (ES/EN/RU), provinces.js
│   ├── data/           # subastas.json, meta.json — обновляются сборщиком
│   └── feed.xml        # RSS новых аукционов
├── scripts/make_demo.py  # демо-данные для предпросмотра
├── tests/test_boe.py     # тесты парсера
└── .github/workflows/update.yml  # расписание + публикация на GitHub Pages
```

## Как это работает

1. Каждые 3 часа GitHub Actions запускает `scraper/scrape.py`.
2. Сборщик ищет на subastas.boe.es аукционы в статусах «Celebrándose» и «Próxima apertura»,
   отсортированные по дате начала, и проходит страницы, пока не встретит уже известные.
3. Для каждого нового ID скачивает три вкладки карточки (общие данные, организатор,
   имущество) и сохраняет нормализованную запись: источник, тип имущества, провинция,
   стоимость, оценка, депозит, даты, кадастровый номер и т. д.
4. Обновляет статусы (идёт / скоро / завершён), удаляет завершённые старше 30 дней.
5. Пишет `site/data/subastas.json`, `site/feed.xml`, коммитит их и публикует сайт на GitHub Pages.
6. Если настроен Telegram — постит каждый новый аукцион в канал (при первом запуске не постит,
   чтобы не засыпать канал сотнями сообщений).

Запросы идут с паузой 1,2 с и с честным User-Agent — портал BOE не нагружается.

## Запуск за 10 минут (GitHub Pages, бесплатно)

1. Создайте репозиторий на GitHub и загрузите в него содержимое этой папки (ветка `main`).
2. **Settings → Pages → Source: GitHub Actions.**
3. **Settings → Secrets and variables → Actions → Variables:**
   - `SITE_URL` — адрес сайта, например `https://ваш-логин.github.io/subastas-espana`
   - `SITE_NAME` — (необязательно) название для RSS и Telegram
4. **Actions → «Обновление аукционов и публикация сайта» → Run workflow.**
   Первый запуск загружает около 1–2 тыс. аукционов и занимает 20–40 минут, следующие — пару минут.
5. Сайт доступен по адресу из шага 3. Дальше всё обновляется само.

### Telegram-канал (автопубликация)

1. Создайте бота у @BotFather, получите токен.
2. Создайте канал, добавьте бота администратором.
3. В **Secrets** добавьте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` (`@имя_канала` или числовой ID).
4. В `site/config.js` укажите `telegramUrl: "https://t.me/имя_канала"` — на сайте появится кнопка подписки.

## Альтернатива: свой сервер (VPS)

Если BOE начнёт отклонять запросы с серверов GitHub, запускайте сборщик на своём сервере
(лучше с испанским IP):

```bash
pip install -r requirements.txt
SITE_URL=https://ваш-домен.es python3 scraper/scrape.py
```

`crontab -e`:
```
17 6-21/3 * * * cd /srv/subastas && SITE_URL=https://ваш-домен.es python3 scraper/scrape.py >> scrape.log 2>&1
```
Отдавайте папку `site/` через nginx/Caddy — это обычная статика.

## Локальный просмотр

```bash
python3 scripts/make_demo.py      # демо-данные (вымышленные, с плашкой «демо»)
cd site && python3 -m http.server 8000
# откройте http://localhost:8000
```
Открывать `index.html` двойным кликом нельзя — браузер не загрузит JSON с `file://`.

## Настройки сборщика (переменные окружения)

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `SCRAPER_DELAY` | `1.2` | пауза между запросами, сек |
| `SCRAPER_STATES` | `EJ,PU` | статусы для поиска (EJ — идёт, PU — скоро откроется) |
| `MAX_PAGES` / `--max-pages` | `10` | страниц поиска на статус (по 50 аукционов) |
| `MAX_NEW` / `--max-new` | `300` | максимум новых карточек за запуск |
| `KEEP_FINISHED_DAYS` | `30` | сколько дней показывать завершённые |
| `TELEGRAM_MAX_POSTS` | `20` | лимит постов в Telegram за запуск |

## Что важно знать

- **Разметка BOE.** Парсер написан под текущую структуру страниц subastas.boe.es и покрыт
  тестами (`python3 tests/test_boe.py`). Если портал изменит вёрстку, правки нужны только в `scraper/boe.py`.
  После первого реального запуска загляните в `site/data/subastas.json` и проверьте, что
  суммы, даты и провинции заполнены.
- **Seguridad Social** проводит аукционы на своём портале — сейчас они не собираются;
  это отдельный источник, его можно добавить в `scraper/` аналогично.
- **Карта** показывает аукционы по центрам провинций (точные координаты BOE не публикует).
  В карточке есть ссылки на Google Maps и Кадастр.
- **Атрибуция.** Данные BOE можно повторно использовать с указанием источника — подпись уже есть в подвале сайта и в `meta.json`.
  Сайт должен оставаться независимым: собственное название и дизайн, без логотипов BOE.
- **Персональные данные.** В судебных аукционах фигурирует имущество должников; сайт публикует
  только то, что уже публично на портале BOE, и не собирает имена.

## Идеи для развития

- Email-уведомления по сохранённым поискам (нужен бэкенд: Supabase/Firebase + рассылка).
- Точные координаты через геокодирование адресов (Nominatim/CartoCiudad) с кешем.
- История ставок (вкладка «Pujas») и статистика скидок к оценке по провинциям.

## Регистрация и доступ (Supabase)

Когда в `site/config.js` заполнены `supabaseUrl` и `supabaseAnonKey`, сайт работает в закрытом режиме:

| Кто | Что видит |
|---|---|
| Гость / пользователь без доступа | 10 самых свежих текущих аукционов и все завершённые |
| Пользователь с активным сроком | всё |
| Доверенный адрес (`trusted_emails`) | всё, без ограничения срока и без проверок на дубли |

Ограничение работает на сервере (Row Level Security): закрытые аукционы просто не отдаются браузеру,
обойти это через код страницы нельзя. RSS и Telegram публикуют только анонсы (тип, место, цена) со ссылкой на сайт.

### Управление (Supabase → Table Editor)

- **Срок для новых пользователей** — таблица `settings`, строка `default_trial_until` (сейчас `2027-12-31`).
  Меняет срок только для тех, кто зарегистрируется после изменения.
- **Срок конкретного пользователя** — таблица `profiles`, колонка `access_until` (дата включительно).
  Пусто = доступа нет. Удобный список — представление `admin_users`.
- **Доверенные адреса** — таблица `trusted_emails`, Insert row → `email`. Регистр букв, точки и `+метки` в Gmail не важны.
- **Почему отказано в бесплатном периоде** — `profiles.trial_denied_reason`:
  `duplicate_email` (тот же Gmail с точками/+меткой), `disposable_email` (одноразовая почта),
  `duplicate_device` (тот же браузер, или тот же отпечаток устройства с того же IP); в `duplicate_of` — с кем совпал.
  Если это ошибка (например, общий семейный компьютер) — просто впишите дату в `access_until`.

Полезные SQL-запросы (SQL Editor):
```sql
-- продлить всем, у кого доступ кончается 31.12.2027, до 30.06.2028
update profiles set access_until = '2028-06-30' where access_until = '2027-12-31';
-- кто получил отказ как дубль
select * from admin_users where trial_denied_reason is not null;
```

### Защита от повторной регистрации — как устроена
1. Адреса «склеиваются»: `Ivan.Petrov+1@gmail.com` = `ivanpetrov@gmail.com`.
2. Одноразовые почтовые сервисы (yopmail, mailinator и др., список в `disposable_domains`) бесплатный период не получают.
3. При первом входе нового аккаунта сайт передаёт ID браузера (хранится в браузере) и отпечаток устройства.
   Совпал ID браузера с другим аккаунтом, или отпечаток + IP — бесплатного периода нет.
Это базовая защита: человек со вторым устройством и другой сетью её обойдёт. Надёжнее — подтверждение телефона по SMS (платно).
На сайте есть уведомление о сборе технического идентификатора; добавьте его и в свою политику конфиденциальности.
